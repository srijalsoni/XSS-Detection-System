# P_211 Application Architecture Documentation

## 1. System Overview
The **P_211 Defensive Web Application** is designed to provide real-time Cross-Site Scripting (XSS) attack detection, prevention, and security monitoring.

In Phase 6, the **Security Monitoring Dashboard & Telemetry Analytics** subsystem was introduced to visualize security telemetry.
In Phase 7, the **Machine Learning Classifier Layer** was introduced as a secondary, advisory layer that complements the authoritative deterministic detection engine.

## 3. End-to-End System Components

```
User / Browser / Security Analyst
      |
      v
Flask Application Factory (app.py)
      |
      +-- Request ID Middleware (X-Request-ID attached to g and response headers)
      +-- Security Headers Middleware (Content-Security-Policy, X-Content-Type-Options, etc.)
      +-- Config & Logger (config.py, logger.py)
      |
      +-- Blueprint Routing
            +-- Main Blueprint (routes/main_routes.py: /, /health)
            +-- Feature Blueprint (routes/feature_routes.py: /search, /comments, /profile)
            |         |
            |         +-- Server-Side Input Validation (Presence, Length Limits, URL Scheme Validation)
            |         +-- Input Normalization (security/normalization.py)
            |         +-- Authoritative Rule Engine (security/detector.py: XSS-001..006)
            |         +-- Secondary ML Classifier (ml/predictor.py -> ml_label, ml_confidence)
            |         +-- Response Policy Engine (security/policy.py: ALLOW, LOG_ONLY, SAFE_RENDER, REJECT, BLOCK)
            |         +-- Response Handlers (security/response.py -> blocked.html)
            |
            +-- Dashboard Blueprint (routes/dashboard_routes.py: /dashboard, /api/security/*)
                      |
                      v
              Dashboard Repository (database/dashboard_repository.py)
                      | (Optimized SQL Aggregation: COUNT, GROUP BY, WHERE, ORDER BY)
                      v
              SQLite Database (database/app.db: security_events, application_events)
                      |
                      v
      Presentation & Visualization Layer
            +-- Jinja2 Presentation Templates (templates/*.html, templates/dashboard.html)
            +-- Static Assets (static/css/dashboard.css, static/js/dashboard.js)
            +-- Local Vendor Visualizations (static/js/vendor/chart.umd.js)
            +-- Sanitized Error Handlers (404, 500 JSON without stack/path leaks)
```

## 4. Telemetry & Machine Learning Advisory Integration

```
Security Events (Generated by /search, /comments, /profile)
  Includes details: {
    matched_rules: [...],
    ml_label: "SUSPICIOUS" | "BENIGN",
    ml_confidence: 0.9965,
    ml_model_version: "1.0.0",
    ml_enabled: true
  }
      |
      v
SQLite security_events Table (Indexed by created_at, risk_level, event_type)
      |
      v
Dashboard Repository (Server-Side SQL Aggregation)
      |
      v
RESTful Telemetry APIs (/api/security/summary, risk, actions, rules, endpoints, timeline, recent)
      |
      v
Browser Dashboard UI (/dashboard)
      |-- Summary Cards (Total, Critical, High, Blocked)
      |-- Timeline Chart (Line: Activity Over Time)
      |-- Risk Chart (Doughnut: Risk Level Distribution)
      |-- Action Chart (Bar: Response Actions Applied)
      |-- Rule Chart (Horizontal Bar: Rule Trigger Frequency)
      |-- Endpoint Chart (Doughnut: Target Attack Surfaces)
      |-- Recent Events Table (Safe Telemetry via Safe DOM APIs)
```
